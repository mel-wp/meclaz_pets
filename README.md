# Meclaz Pets

Aplicativo de adoção de animais desenvolvido com Flutter, Dart e PostgreSQL.

O Meclaz Pets tem como objetivo facilitar a divulgação de animais disponíveis para adoção e permitir que pessoas interessadas enviem solicitações diretamente pelo aplicativo.

O sistema possui uma API REST própria, responsável pela comunicação entre o aplicativo e o banco de dados, além de uma área administrativa protegida por autenticação.

---

## Funcionalidades

- Visualização de animais disponíveis para adoção.
- Cadastro de animais realizado exclusivamente por administradores.
- Envio de solicitações de adoção.
- Login individual para administradores.
- Autenticação utilizando JWT.
- Proteção de senhas com BCrypt.
- API REST para integração com outros aplicativos.
- Documentação dos endpoints dentro do aplicativo.

## Tecnologias utilizadas

| Tecnologia | Utilização |
|---|---|
| Flutter | Interface do aplicativo |
| Dart | Linguagem do aplicativo e da API |
| PostgreSQL | Banco de dados |
| pgAdmin | Administração do banco |
| HTTP | Comunicação entre aplicativo e API |
| JWT | Autenticação |
| BCrypt | Criptografia das senhas |

# 4. Configuração do banco de dados PostgreSQL

Esta etapa é muito importante!

O projeto utiliza um banco de dados chamado `meclaz_pets`, que armazena os animais, os usuários administradores e as solicitações de adoção.

Cada computador precisa ter o PostgreSQL instalado e o banco configurado.

## 4.1. Criar o banco de dados

1. Abra o pgAdmin.
2. Conecte-se ao servidor PostgreSQL.
3. Clique com o botão direito em **Databases**.
4. Selecione **Create → Database**.
5. No campo Database, digite:

```text
meclaz_pets
```

6. Clique em **Save**.

## 4.2. Abrir o Query Tool

Agora precisamos criar as tabelas.

1. No pgAdmin, expanda a opção Databases.
2. Clique no banco `meclaz_pets`.
3. Clique com o botão direito sobre ele.
4. Selecione **Query Tool**.
5. Uma janela para executar comandos SQL será aberta.

## 4.3. Criar a tabela `animais`

Essa tabela armazena os animais cadastrados pela ONG ou pelos administradores.

Execute:

```sql
CREATE TABLE IF NOT EXISTS animais (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    especie VARCHAR(50) NOT NULL,
    idade_em_meses INTEGER NOT NULL CHECK (idade_em_meses >= 0),
    disponivel BOOLEAN NOT NULL DEFAULT TRUE
);
```

### O que cada coluna significa?

| Coluna | Tipo | Função |
|---|---|---|
| id | INTEGER | Identificador único do animal |
| nome | VARCHAR(100) | Nome do animal |
| especie | VARCHAR(50) | Espécie, como cachorro ou gato |
| idade_em_meses | INTEGER | Idade do animal em meses |
| disponivel | BOOLEAN | Indica se está disponível para adoção |

O campo `id` é gerado automaticamente pelo PostgreSQL.

O campo `disponivel` começa como `TRUE`, ou seja, o animal estará disponível para adoção quando for cadastrado.

## 4.4. Criar a tabela `usuarios`

Essa tabela armazena os dados dos administradores autorizados a acessar a área administrativa.

Execute:

```sql
CREATE TABLE IF NOT EXISTS usuarios (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    senha_hash TEXT NOT NULL,
    tipo VARCHAR(20) NOT NULL DEFAULT 'admin',
    ativo BOOLEAN NOT NULL DEFAULT TRUE,
    criado_em TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### O que cada coluna significa?

| Coluna | Tipo | Função |
|---|---|---|
| id | INTEGER | Identificador do usuário |
| nome | VARCHAR(100) | Nome do administrador |
| email | VARCHAR(150) | E-mail utilizado no login |
| senha_hash | TEXT | Senha armazenada em formato protegido |
| tipo | VARCHAR(20) | Tipo de usuário; administradores usam `admin` |
| ativo | BOOLEAN | Indica se a conta está ativa |
| criado_em | TIMESTAMP | Data e horário do cadastro |

**Importante:** a senha não deve ser inserida diretamente nessa tabela. O script `criar_admin.dart` gera o hash BCrypt e realiza o cadastro corretamente.

## 4.5. Criar a tabela `solicitacoes`

Essa tabela registra as pessoas interessadas em adotar os animais.

Execute:

```sql
CREATE TABLE IF NOT EXISTS solicitacoes (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    animal_id INTEGER NOT NULL REFERENCES animais(id),
    nome_interessado VARCHAR(100) NOT NULL,
    contato VARCHAR(150) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pendente'
);
```

### O que cada coluna significa?

| Coluna | Tipo | Função |
|---|---|---|
| id | INTEGER | Identificador da solicitação |
| animal_id | INTEGER | Identifica o animal relacionado ao pedido |
| nome_interessado | VARCHAR(100) | Nome da pessoa interessada |
| contato | VARCHAR(150) | Contato informado pela pessoa |
| status | VARCHAR(20) | Situação da solicitação |

O campo `animal_id` é uma chave estrangeira que referencia a tabela `animais`.

Isso significa que uma solicitação precisa estar relacionada a um animal cadastrado.

O status inicial é `pendente`.

## 4.6. Conferir se as tabelas foram criadas

No pgAdmin:

1. Expanda `meclaz_pets`.
2. Expanda **Schemas**.
3. Expanda **public**.
4. Expanda **Tables**.

Devem aparecer:

- `animais`
- `usuarios`
- `solicitacoes`

Se elas não aparecerem imediatamente, clique com o botão direito em Tables e selecione Refresh.

# 5. Cadastrar administradores

Depois de criar as três tabelas, é possível cadastrar os usuários que terão acesso à área administrativa.

O projeto utiliza o arquivo `criar_admin.dart` para essa tarefa.

## 5.1. Abrir a pasta da API

No PowerShell:

```powershell
cd meclaz_pets\api_adocao
```

Instale as dependências:

```powershell
dart pub get
```

## 5.2. Executar o cadastro

Execute:

```powershell
dart run .\bin\criar_admin.dart
```

O terminal solicitará:

1. Senha do PostgreSQL.
2. Nome do administrador.
3. E-mail.
4. Senha da conta administrativa.

A senha da conta precisa ter pelo menos 8 caracteres.

Repita o procedimento para cada pessoa que deverá ter acesso administrativo.

Cada integrante terá seu próprio e-mail e senha.

**Atenção:** não é necessário inserir usuários manualmente no pgAdmin. Utilize o script para que as senhas sejam protegidas corretamente.

# 6. Configurar e iniciar a API

A API é responsável por conectar o aplicativo ao PostgreSQL.

Abra um terminal na pasta:

```powershell
cd meclaz_pets\api_adocao
```

Instale as dependências:

```powershell
dart pub get
```

## 6.1. Gerar a chave JWT

A API utiliza uma chave secreta para assinar e validar os tokens de autenticação.

No PowerShell, execute:

```powershell
$bytes = New-Object byte[] 48
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$env:JWT_SECRET = [Convert]::ToBase64String($bytes)
```

Essa chave é gerada para a sessão atual do terminal.

Não compartilhe essa chave e não a envie para o GitHub.

## 6.2. Iniciar o servidor

Execute:

```powershell
dart run .\bin\api_adocao.dart
```

O terminal solicitará a senha do PostgreSQL.

A API utiliza:

| Configuração | Valor |
|---|---|
| Host | localhost |
| Porta do PostgreSQL | 5432 |
| Banco | meclaz_pets |
| Usuário PostgreSQL | postgres |
| Porta da API | 8080 |

Após a conexão, deverá aparecer uma mensagem indicando que a API está rodando.

**Não feche esse terminal enquanto estiver utilizando o aplicativo.**

Entre na pasta:

```powershell

```


Abra o emulador Android pelo Android Studio.

No terminal, execute:


O aplicativo deverá abrir no emulador.

**Observação:** se o emulador for reiniciado, execute novamente o comando `adb reverse`.

# 🌐 9. Documentação dos endpoints da API

Endereço local da API:

```text
http://127.0.0.1:8080
```

| Método | Endpoint | Descrição | Autenticação |
|---|---|---|---|
| POST | `/login` | Realiza login administrativo | Não |
| GET | `/animais` | Consulta todos os animais | Não |
| GET | `/animais?disponivel=true` | Consulta animais disponíveis | Não |
| POST | `/animais` | Cadastra um animal | JWT de administrador |
| POST | `/solicitacoes` | Registra uma solicitação de adoção | Não |

## 9.1. Login

Endpoint:

```text
POST /login
```

Exemplo de corpo JSON:

```json
{
  "email": "admin@email.com",
  "senha": "sua_senha"
}
```

Em caso de sucesso, a API retorna um token JWT e os dados do administrador.

## 9.2. Consultar animais

Endpoint:

```text
GET /animais
```

Para consultar somente animais disponíveis:

```text
GET /animais?disponivel=true
```

## 9.3. Cadastrar animais

Endpoint:

```text
POST /animais
```

Exemplo:

```json
{
  "nome": "Bob",
  "especie": "Cachorro",
  "idade_em_meses": 24
}
```

É obrigatório enviar o token de administrador no cabeçalho:

```text
Authorization: Bearer SEU_TOKEN
```

## 9.4. Registrar solicitação de adoção

Endpoint:

```text
POST /solicitacoes
```

Exemplo:

```json
{
  "animal_id": 1,
  "nome_interessado": "Maria",
  "contato": "maria@email.com"
}
```

O animal precisa existir e estar disponível para adoção.

### Sobre o banco de dados

O banco de dados PostgreSQL é independente do repositório GitHub.

Isso significa que:

- O código é compartilhado pelo GitHub.
- As tabelas precisam ser criadas no PostgreSQL de cada computador.
- Os dados cadastrados localmente não são enviados automaticamente ao GitHub.
- Cada pessoa terá seu próprio banco enquanto a aplicação estiver rodando localmente.

Para todos utilizarem os mesmos animais e solicitações simultaneamente, será necessário hospedar a API e o PostgreSQL em um servidor acessível pela internet.

# 11. Problemas comuns

### Erro: porta 8080 ocupada

Execute:

```powershell
netstat -ano | findstr :8080
```

Identifique o PID do processo e finalize-o:

```powershell
taskkill /PID NUMERO_DO_PID /F
```

### Erro: não foi possível conectar ao PostgreSQL

Confira:

- Se o serviço PostgreSQL está iniciado.
- Se o banco `meclaz_pets` foi criado.
- Se a senha informada está correta.
- Se o usuário PostgreSQL é `postgres`.
- Se as três tabelas foram criadas.

### Erro: aplicativo não acessa a API

Confira se:

- A API está rodando.
- O emulador está aberto.
- O comando `adb reverse` foi executado.
- O aplicativo foi iniciado com o endereço correto.

### Erro: JWT_SECRET não configurada

Gere novamente a chave no PowerShell e inicie a API no mesmo terminal.

### Erro: administrador não consegue entrar

Confira se:

- O administrador foi criado pelo script `criar_admin.dart`.
- O e-mail está correto.
- A senha está correta.
- A conta está ativa no banco de dados.
